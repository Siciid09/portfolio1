Chapter 1: Intro to MVC

Chapter 1: Introduction to ASP.NET MVC

What does MVC stand for and how is it used in software engineering?
MVC stands for Model, View, and Controller. The MVC architectural pattern has existed for a long time in software engineering. Almost all languages use MVC with slight variation, but conceptually it remains the same. MVC separates the application into three components.
Define the "Model" component in detail.
Model represents the shape of the data and business logic. It maintains the data of the application. Model objects retrieve and store model state in a database. Simply put: Model is data and business logic.
Define the "View" component.
View is a user interface. View displays data using the model to the user and also enables them to modify the data.
Define the "Controller" component and its interaction flow.
Controller handles the user request. Typically, users interact with the View, which in-turn raises an appropriate URL request. This request will be handled by a controller. The controller renders the appropriate view with the model data as a response. Simply put: Controller is a request handler.
Describe the precise flow of a user's request (Request/Response) in MVC Architecture.
When the user enters a URL in the browser (e.g., http://mydomain.com/home/about), it goes to the server and calls the appropriate controller. Then, the Controller uses the appropriate View and Model, creates the response, and sends it back to the user's browser.
Where does the text suggest visiting to learn MVC in detail?
Visit MSDN to learn MVC in detail.

Exact Points to Remember (As stated in Chapter 1):

  • 1. MVC stands for Model, View and Controller.
  • 2. Model is responsible for maintaining application data and business logic.
  • 3. View is a user interface of the application, which displays the data.
  • 4. Controller handles user's requests and renders appropriate View with Model data.

Chapter 2: Building Your First MVC Application

What are the exact steps to create a new ASP.NET MVC 4 web application?
1. Open visual studio
2. Click File > New Project
3. Select "Web" from "Installed Templates" section
4. Select ASP.NET MVC 4 Web Application
5. Set Name="MVCDemo"
6. Click OK
7. Select "Empty" template.
8. Select "Razor" as the ViewEngine.
What are the two built-in view engines, and which is preferred?
There are 2 built-in view engines - Razor and ASPX. Razor is preferred by most MVC developers.
What folders are automatically created in the solution explorer?
Models, Views, and Controllers folders. They contain Models, Views, and Controllers respectively.
How do you add a Controller named "HomeController"?
Right Click on "Controllers" folder > Select Add > Controller > Set Controller Name = HomeController > Leave rest of defaults and click "Add". This adds `HomeController.cs`.
If you run the application (CTRL+F5) right after adding the controller, what EXACT error do you get and what locations are searched?
You get: Server Error in '/' Application. "The view 'Index' or its master was not found or no view engine supports the searched locations."
The searched locations are exactly:
~/Views/Home/Index.aspx
~/Views/Home/Index.ascx
~/Views/Shared/Index.aspx
~/Views/Shared/Index.ascx
~/Views/Home/Index.cshtml
~/Views/Home/Index.vbhtml
~/Views/Shared/Index.cshtml
~/Views/Shared/Index.vbhtml
Besides adding a view named "Index", what is another way to fix this error?
Change the return type of the `Index()` function from "ActionResult" to "string", and return the string "Hello from MVC Application" instead of `View()`.
By default, Visual Studio uses the built-in asp.net development server. What are the exact steps to use IIS instead?
1. In solution explorer, right click on the project and select "Properties"
2. Click on "Web" tab
3. Select "Use Local IIS Web Server" radio button
4. Notice Project Url is set to http://localhost/MVCDemo by default
5. Click on "Create Virtual Directory" button.
What is the most important difference regarding URL mapping between MVC and Web Forms?
In MVC, the URL is mapped to a controller action method (e.g., http://localhost/MVCDemo/Home/index maps to Controller "Home", Method "Index").
Whereas in Web Forms application, the URL is mapped to a physical file. For example, in a web application, if we have to display the same message, we add a webform and in the `Page_load()` event include Response.Write("Hello from ASP.NET Web Forms Application");. We then access WebForm1.aspx physically at http://localhost/WebFormsApplication/WebForm1.aspx.

Chapter 3: Controllers and Views in MVC

Where is the URL mapping (http://localhost/MVCDemo/Home/Index) defined in the application?
The mapping is defined in Global.asax within the RegisterRoutes() method, which is implemented in the RouteConfig class.
What is the structure of the default route mapped in RouteConfig?
The URL structure is {controller}/{action}/{id}. The defaults are: controller = "Home", action = "Index", id = UrlParameter.Optional.
What happens if you navigate to /Home/Index/10 with an unmodified controller? How do you fix it to read the "id"?
Nothing happens initially. You must change the `Index()` function to accept a parameter: `public string Index(string id)`. Then the value "10" is passed to the `id` parameter.
How do you read both an ID and a query string named "name" (e.g., ?name=Pragim)?
You can modify the method signature to: `public string Index(string id, string name)`. Alternatively, just like in web forms, you can use `Request.QueryString["name"]` inside the method.
What happens if an Action method returns a `List<string>` of countries (India, US, UK, Canada)?
The output is not as expected. It literally renders the object type to the screen: System.Collections.Generic.List`1[System.String].
What are the steps to add a Razor View for the Index function?
Right click on the Index() function > Click on "Add View" > Notice view name matches action method name > Select "Razor" as view engine > Leave rest of defaults > Click "Add". The @ symbol is used to switch between HTML and C# code.
Explain ViewData in detail.
ViewData is a dictionary of objects stored and retrieved using strings as keys. Its syntax is very similar to ViewState, SessionState, and ApplicationState. It does not provide compile-time error checking (misspelled keys are only caught at runtime).
Explain ViewBag in detail.
ViewBag uses the dynamic feature introduced in C# 4.0, allowing properties to be dynamically added. Internally, ViewBag properties are stored as name/value pairs in the ViewData dictionary. Like ViewData, it does not provide compile-time error checking.
What is the recommended "good practice" over using ViewBag/ViewData?
It is always a good practice to pass data from a controller to a view using strongly typed view models.
How do you create an Employee model and add it to the Controller?
Right click "Models" folder > Add > Class > Name it Employee.cs. Inside `EmployeeController.cs`, include `using MVCDemo.Models;`. Create an instance of `Employee` in the `Details()` method, populate properties (Id: 101, Name: John, Gender: Male, City: London), and pass it via `return View(employee);`.
How do you create a strongly typed view for the Employee model, and what happens if you forget to pass the object to the View?
Right click Details() > Add View > Check "Create strongly typed view" > Select "Employee (MVCDemo.Models)" from dropdown. (Note: If not visible, build project first).
If you do NOT pass the object (e.g., using just `return View();`), navigating to /Employee/Details gives a runtime error: "Object reference not set to an instance of an object."

Chapter 4: Views in MVC (Data Access)

What is the role of the Model in data access, and what can a Model be?
The controller responds to a URL request, gets data from a model, and hands it over to the view. Model can be entities or business objects.
What are the steps to retrieve data from `tblEmployee` using Entity Framework?
Step 1: Install entity framework, if you don't have it installed already on your computer. At the time of this recording the latest version is 5.0.0.0. Using nuget package manager, is the easiest way to install. A reference to EntityFramework.dll is automatically added. Open visual studio > Tools > Library Package Manager > Manage NuGet Packages for Solution.
Step 2: Add `EmployeeContext.cs` to Models folder. Include `using System.Data.Entity;`. Class derives from `DbContext` and has `DbSet<Employee>`.
Step 3: Include connection string in `web.config` inside ``.
Step 4: Map "Employee" model to database table "tblEmployee" using `[Table("tblEmployee")]` attribute (requires `System.ComponentModel.DataAnnotations.Schema`).
Step 5: In `EmployeeController`, query DB: `Employee employee = employeeContext.Employees.Single(x => x.EmployeeId == id);`

Complete Course Summary (Chapters 1-4)

Chapter 1 Summary

ASP.NET MVC is an architectural pattern that separates a web application into three distinct layers. The Model is responsible for the shape of the data and business logic, retrieving and storing state in a database. The View acts as the user interface, displaying data to the user. The Controller is the request handler; it intercepts URL requests from the browser, gathers data from the Model, and passes that data to the View to formulate the HTTP response.

Chapter 2 Summary

Building an MVC app in Visual Studio involves creating a project using the Razor View Engine (which is preferred over ASPX). The framework relies on a specific folder structure: Models, Views, and Controllers. An essential concept learned is that unlike Web Forms (where URLs map to physical files like .aspx), MVC maps URLs directly to Controller Action Methods. If a Controller attempts to return a View that hasn't been created, IIS will search specific file paths (.aspx, .cshtml) and throw a "Server Error in '/' Application". You can bypass views entirely by returning a raw string.

Chapter 3 Summary

Routing is defined in `Global.asax` via `RouteConfig`, establishing the default `{controller}/{action}/{id}` format. Action methods can easily accept URL parameters (`id`) or QueryStrings (`?name=`). To pass data from the Controller to the View, developers can use `ViewData` (a dictionary using string keys) or `ViewBag` (a C# 4.0 dynamic object). Because both compile internally to the same dictionary and lack compile-time error checking, the best practice is to use Strongly Typed View Models. This involves creating a C# class (like `Employee`), instantiating it in the Controller, passing it via `return View(employee)`, and binding it to a Razor View using the `@model` directive.

Chapter 4 Summary

To access persistent data in a database table (like `tblEmployee`), Entity Framework (v5.0.0.0) is utilized via NuGet. A custom Context class (e.g., `EmployeeContext`) inheriting from `DbContext` is created to establish the DB connection based on connection strings set in `web.config`. The C# Model is explicitly mapped to the SQL table using the `[Table("tblEmployee")]` attribute. Data is queried in the Controller using LINQ (`.Single()`), and for existing databases, default initialization is disabled in `Global.asax`.

Chapter 3: RouteConfig and Parameters

RouteConfig.csC#
public static void RegisterRoutes(RouteCollection routes)
{
    routes.IgnoreRoute("{resource}.axd/{*pathInfo}");

    routes.MapRoute(
        name: "Default",
        url: "{controller}/{action}/{id}",
        defaults: new { controller = "Home", action = "Index", id = UrlParameter.Optional }
    );
}
Book Explanation: The mapping is defined in Global.asax calling RouteConfig. This method has a default route. If a URL does not have an id, it is not a problem because id is Optional in the default route.
HomeController.csC#
// Read ID and QueryString
public string Index(string id, string name)

    return "The value of Id = " + id + " and Name = " + name;

Book Explanation: Change the Index() function to read both the parameter values. Just like web forms, you can also use "Request.QueryString" to read the `name` parameter from the URL.

Chapter 3: ViewData vs ViewBag Data Transfer

Chapter 3: Strongly Typed Views

Employee.cs & EmployeeController.csC#
public class Employee
{
    public int EmployeeId { get; set; }
    public string Name { get; set; }
    public string Gender { get; set; }
    public string City { get; set; }
}

// Inside EmployeeController.cs
public ActionResult Details()
{
    Employee employee = new Employee()
    {
        EmployeeId = 101,
        Name = "John",
        Gender = "Male",
        City = "London"
    };
    return View(employee);
}
Book Explanation: To encapsulate Employee information, add Employee class. In EmployeeController, change the action to Details(). Create an instance of Employee class and hard code data. To fix the "Object reference not set" error, pass the "Employee" object to the view via the `return View(employee);` statement.

Book Explanation: Create a strongly typed view referencing the Employee class. The `@model` directive dictates the type, allowing the view to generate HTML using `@Model.PropertyName` and send it to the requested client.

Chapter 4: Data Access using Entity Framework

EmployeeContext.cs & web.configC#/XML
using System.Data.Entity;

public class EmployeeContext : DbContext
{
    public DbSet<Employee> Employees { get; set; }
}

<!-- Inside web.config root -->
<connectionStrings>
    <add name="EmployeeContext"
         connectionString="server=.; database=Sample; integrated security=SSPI"
         providerName="System.Data.SqlClient"/>
</connectionStrings>
Book Explanation: Step 2: EmployeeContext class derives from DbContext class, and is responsible for establishing a connection to the database. Step 3: Add a connection string to the web.config file in the root directory.
Employee mapping & QueryingC#
// Step 4: Map Model
[Table("tblEmployee")]
public class Employee
{
    public int EmployeeId { get; set; }
    // ... other properties
}

// Step 5: EmployeeController.cs Details(int id)
public ActionResult Details(int id)
{
    EmployeeContext employeeContext = new EmployeeContext();
    Employee employee = employeeContext.Employees.Single(x => x.EmployeeId == id);
    return View(employee);
}

// Step 6: Global.asax Application_Start()
Database.SetInitializer<MVCDemo.Models.EmployeeContext>(null);
Book Explanation: Step 4: Map Employee model class to the database table `tblEmployee` using `Table` attribute. Step 5: Use `Single()` to find the correct record by ID. Step 6: Existing databases do not need database initializer so it can be turned off using `SetInitializer(null)`.
